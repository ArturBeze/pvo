# Сканирование и слежение

`scan_track.py` — новый скрипт OpenCV + pyFirmata2. Старый `view_camera.py`
остаётся обычным просмотрщиком; держите его рядом: новый скрипт использует его
функции обработки и отрисовки. Tkinter не используется.

## Запуск на Raspberry Pi

Используйте окружение, в котором работает камера. Установите pyFirmata2:

```sh
python -m pip install pyFirmata2
python tof_opencv/scan_track.py
```

Arduino Uno должен работать с StandardFirmata, как для `clue/servo.py`.
Порт по умолчанию определяется автоматически (`--port auto`): сначала ищется
устройство Arduino по USB-описанию/VID, затем распространённые USB-мосты клонов
CH340/CH341, CP210x и FT232. USB-мост сам по себе не подтверждает наличие Firmata.
Если кандидатов несколько или подходящего устройства нет, скрипт сообщает об этом;
можно задать порт вручную: `--port /dev/ttyACM0`. Выбранный порт печатается в консоли.
[Документация pyFirmata2](https://github.com/berndporr/pyFirmata2).
Ось X — цифровой pin 9, ось Y — pin 10. Питание сервоприводов должно
соответствовать их току, земля питания и Arduino — общая.

Сразу после подключения приводам задаётся положение 90°/90° (или ближайшее
разрешённое, если задан более узкий сектор). После секунды на позиционирование
камера начинает движение к началу сектора. Положение серво не измеряется:
в интерфейсе показаны заданные углы, а не показания датчиков.

Проверка камеры, распознавания и расчёта углов **без подключения Arduino**:

```sh
python tof_opencv/scan_track.py --no-servos
```

Этот режим требует настоящую камеру, но не управляет приводами.

Чтобы камера только двигалась змейкой и показывала глубину, без обнаружения цели
и переключения на слежение:

```sh
python tof_opencv/scan_track.py --scan-only
```

Флаг `--scan-only` по умолчанию выключен. Без него действуют режимы SCAN/TRACK/WAIT.
С ним фильтры изображения остаются активными, но поиск фрагментов не выполняется;
параметры слежения и ожидания потери не используются. Камера по-прежнему нужна.

## Режимы

- **SCAN**: горизонтальный проход по X, переход на следующую строку по Y,
  обратный горизонтальный проход. На краю диапазона Y направление строк меняется.
- **TRACK**: ближайший подходящий фрагмент становится целью. Контроллер старается
  совместить его центр тяжести с центром изображения; в центральной мёртвой зоне
  коррекция не выполняется. Слежение ограничено разрешёнными углами.
- **WAIT**: если цель не обнаружена, держатся последние углы. Если она появляется
  снова в пределах допуска сопоставления, слежение продолжается. Через 3 секунды
  после последнего обнаружения возобновляется SCAN с текущего положения.

Диапазон **400–500 мм** означает допустимую глубину точки, а не угловое поле
зрения камеры. Фрагмент также должен проходить confidence и минимальную площадь.
Выход за диапазон глубины, падение confidence или уменьшение площади ниже порога
тоже считаются потерей цели.

При слежении кандидаты сопоставляются по центру и медианной глубине. Новая
более близкая цель в другой части кадра не перехватывает слежение немедленно.
Это геометрическое сопоставление: одинаковые объекты при пересечении могут
перепутаться, резкое движение или изменение ракурса — привести к потере цели.
Без нового кадра команды движения не отправляются; после пяти секунд без кадров
скрипт завершается с ошибкой. Нативный SDK должен соблюдать тайм-аут requestFrame.

Контур и кружок отмечают цель, крест — центр изображения. Под картинкой показаны
площадь (пиксели), медианная глубина и confidence. Сверху — состояние и заданные
углы. Те же данные раз в секунду выводятся в консоль. Выход: Q / Esc / закрытие окна.
При выходе вызывается board.exit(): серво отключаются от Firmata; возврата на 90° нет.

## Аргументы

Прежние параметры сохранены, но min/max по умолчанию теперь 400/500:

```sh
python tof_opencv/scan_track.py --port /dev/ttyACM0 \
  --confidence 200 --min 400 --max 500 --tolerance 50 --min-area 80 \
  --lost-timeout 3
```

| Параметр | По умолчанию | Значение |
|---|---:|---|
| `--confidence` | 200 | Минимум confidence, единицы SDK |
| `--min`, `--max` | 400, 500 | Границы глубины, мм |
| `--tolerance` | 50 | Перепад глубины соседних пикселей, мм |
| `--min-area` | 80 | Минимальная площадь фрагмента, пиксели |
| `--range`, `--index` | 4000, 0 | Аппаратный диапазон и индекс камеры |
| `--lost-timeout` | 3 | Ожидание после последнего обнаружения, секунды |
| `--x-min`, `--x-max` | 20, 160 | Угловой сектор X |
| `--y-min`, `--y-max` | 30, 150 | Угловой сектор Y |
| `--scan-speed` | 20 | Скорость сканирования, градусов/сек |
| `--scan-step` | 10 | Интервал строк по Y, градусов |
| `--track-speed` | 40 | Максимальная скорость слежения, градусов/сек |
| `--gain` | 30 | Коэффициент коррекции: градусов/сек на единицу ошибки |
| `--dead-zone` | 0.10 | Допуск от центра, доля половины размера кадра |
| `--servo-hz` | 20 | Максимальная частота команд приводам |
| `--match-radius` | 0.30 | Допуск смещения центра в нормированных координатах кадра |
| `--match-depth` | 100 | Допуск изменения медианной глубины цели, мм |

Знак движения зависит от монтажа. Если цель справа, камера должна поворачиваться
к ней, чтобы цель смещалась к центру кадра. Если получается наоборот, добавьте
`--invert-x`; для вертикали аналогично `--invert-y`:

```sh
python tof_opencv/scan_track.py --invert-x --invert-y
```

Для настройки можно сузить сектор, например `--x-min 70 --x-max 110 --y-min 70
--y-max 110`. Внешние ограничения из исходного примера X 20–160° и Y 30–150°
сохраняются. Если камера колеблется вокруг цели, уменьшайте `--gain` или увеличивайте
`--dead-zone`. Интервал строк выбирается с учётом поля зрения вашей камеры.

Обработка — векторная NumPy/OpenCV, очередь кадров в приложении отсутствует,
команды серво ограничены по частоте и отправляются только при изменении угла.
Максимальное изменение за один шаг ограничено интервалом 0.1 секунды, чтобы после
паузы обработки не было скачка команды. Настоящая скорость и устойчивость слежения
зависят от SDK, сервоприводов, их задержки и монтажа; на устройстве здесь не проверены.
