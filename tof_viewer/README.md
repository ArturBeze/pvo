# Просмотр Arducam ToF

Самостоятельная программа первого этапа. Все новые файлы находятся в этой папке;
исходные примеры проекта не изменены. Python 3.10+; рекомендуемая отправная точка —
ваш Python 3.11 с установленным SDK камеры. tkinter — интерфейс, OpenCV — обработка,
Pillow — вывод. Arduino пока не подключается и сервоприводы не двигаются.
При добавлении управления будет использоваться pyFirmata2: X — pin 9, Y — pin 10.

## Запуск

Из корня репозитория, в выбранном виртуальном окружении:

```bash
python -m pip install -r tof_viewer/requirements.txt
python tof_viewer/app.py --demo
python tof_viewer/app.py
```

На Raspberry Pi должны быть настроены драйвер и **ArducamDepthCamera** той версии,
с которой работает `clue/time-of-flight.py`. SDK устанавливается отдельно по
инструкции производителя для вашей камеры и ОС; общий requirements его не меняет.
Программа использует тот же API: Connection.CSI, FrameType.DEPTH,
Control.RANGE, depth_data, confidence_data. Не все модели предоставляют confidence.
Без совместимого массива программа сообщает ошибку, а не подменяет качество.

Для системного Python Raspberry Pi OS tkinter устанавливается через
`sudo apt install python3-tk`. Для Python из pyenv поддержка Tk должна быть
включена при сборке. Проверка: `python -m tkinter`.
Требуется графический сеанс Raspberry Pi либо настроенный удалённый рабочий стол.

```bash
python tof_viewer/app.py --range 2000 --index 0
```

Диапазон 2000 или 4000 мм задаётся при запуске. Индекс SDK не обязательно совпадает
с номером разъёма на плате. По умолчанию используются 4000 мм и индекс 0 как в примере.
В PyCharm выберите `tof_viewer/app.py` в Script path, нужный Python Interpreter,
а для проверки на компьютере добавьте `--demo` в Parameters.
Для переноса через GitHub добавьте папку `tof_viewer`; её `.venv` и кэш исключены.

## Изображения и параметры

- Исходная глубина: измерения без порога confidence; некорректная глубина чёрная.
- Обработанная глубина: отбор, локальное восстановление, пространственное и временное сглаживание.
- Confidence: исходное качество, фиксированная шкала 0…255 только для отображения.
  Фактический минимум/максимум указан в статусе; confidence не является процентом.
- Надёжные измерения: белым показаны точки, прошедшие порог и проверку глубины.
- Восстановленные пиксели: белым показаны оценки, полученные по соседям.

Порог confidence применяется к исходным числам SDK (по умолчанию 30, как в примере).
Глубина обрабатывается в миллиметрах до раскраски. NaN, бесконечности, значения ≤0
и глубина вне диапазона исключаются.

Радиус восстановления задаёт окно соседей. Восстановление выполняется один раз
только по исходным надёжным точкам: нужно минимум 40% окна, но не менее трёх точек.
Среднее используется только если разброс глубины соседей не превышает допустимого
перепада. Край кадра не достраивается; центр больших пропусков остаётся неизвестным.
Это локальная аппроксимация, а не новое измерение. Даже маленькие пропуски возле
границ могут остаться чёрными — снижайте порог осторожно, сверяясь с исходной картой.

Маскированный bilateral усредняет близкие пространственно и по глубине точки,
исключая неизвестные значения. Радиус определяет размер окна, сила в мм — насколько
сильно смешиваются разные глубины. Он уменьшает обычный шум, но не гарантирует
удаление одиночных выбросов с высоким confidence. Большая сила может размывать границы.

Временной фильтр смешивает текущую и предыдущую глубину, если изменение меньше
допустимого перепада. Доля нового кадра 1 отключает накопление. Меньшие значения
уменьшают дрожание, но могут давать шлейф при движении камеры; для вращения начните
с 1. При изменении настроек история сбрасывается. Потерянные измерения не удерживаются.
Изменения параметров применяются к следующим кадрам.

Увеличение изображения выполняется без интерполяции для честного показа пикселей.
Максимум шкалы фиксирован диапазоном камеры. Большие радиусы повышают нагрузку;
FPS показывает цикл захвата и обработки, а не паспортную частоту сенсора.

## Проверка

```bash
python -m unittest discover -s tof_viewer -p 'test_*.py' -v
```

Тесты проверяют пропуски, границы, NaN/Inf, уменьшение шума, временное сглаживание
и неизменность входных данных. `--demo` работает без SDK и Arduino, генерируя шумную
сцену с движущимся объектом и пропусками. Физическую камеру необходимо отдельно
проверить на Raspberry Pi; синтетические тесты не подтверждают работу драйвера.

API производителя: https://www.arducam.com/docs/tof-camera-getting-started/API/Python_API.html
