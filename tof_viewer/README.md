# Arducam ToF

Один файл `app.py`, построенный по `../clue/time-of-flight.py`:
открытие CSI → DEPTH → requestFrame → визуализация → releaseFrame → imshow.
Без потоков, очередей, tkinter, Pillow, демонстрационного генератора и сглаживания.
Вывод в исходном разрешении камеры через OpenCV.

## Запуск

В окружении, где работает исходный пример камеры, из корня проекта:

```bash
python tof_viewer/app.py
```

В PyCharm: Script path — `tof_viewer/app.py`, Interpreter — окружение с SDK камеры
и OpenCV. Нужен графический сеанс и OpenCV с поддержкой окон, не headless-сборка.
`requirements.txt` сохранён без изменений.

## Управление

- Ползунок **View**: 0 — глубина, 1 — confidence.
- Клавиши **0 / D**, **1 / C**, **пробел** также переключают изображение.
- **Confidence threshold** — порог достоверности для глубины (по умолчанию 30,
  как в примере). Значение 0 отключает отбор по порогу.
- **Q / Esc** или крестик окна — выход.

Глубина раскрашивается RAINBOW, как в примере, в диапазоне 0…4000 мм.
Невалидная глубина и точки ниже порога confidence чёрные.
Confidence нормализуется по минимуму и максимуму текущего кадра, как в исходном
примере, и выводится в сером. Поэтому одинаковая яркость в разных кадрах не означает
одинаковое значение confidence. Однородный confidence отображается чёрным.
Порог действует только на изображение глубины.

```bash
python tof_viewer/app.py --range 2000 --index 0 --confidence 30 --stats
```

`--stats` включает FPS вывода в консоль раз в секунду. По умолчанию статистика
отключена, чтобы консоль не тормозила цикл. Поддерживаются диапазоны 2000/4000 мм.

В каждом цикле преобразуется только выбранное изображение. Исходные массивы SDK
не копируются для передачи между потоками и не изменяются. Готовое изображение
имеет собственную память, поэтому кадр SDK освобождается сразу после преобразования,
до вывода. При любой ошибке освобождаются кадр, камера и окно.

Ожидание кадра ограничено 100 мс; при отсутствии кадров более 5 секунд программа
сообщает ошибку. При медленном захвате реакция клавиш может занимать время ожидания
кадра. Частота ограничивается камерой, SDK и графической системой: проверить реальную
скорость нужно на Raspberry Pi, сравнив этот просмотрщик и исходный пример.
