# Arducam ToF — быстрый просмотр

Прямой вывод через окно OpenCV. Выбор: глубина или confidence, без фильтрации.
Tkinter и Pillow для запуска больше не нужны. `requirements.txt` пользователя
оставлен без изменений; минимальные зависимости просмотрщика — numpy и
opencv-python, а для реальной камеры — настроенный ArducamDepthCamera.

## Запуск из корня проекта

```bash
python tof_viewer/app.py
```

Без оборудования: `python tof_viewer/app.py --demo`.
Дополнительные параметры: `--range 2000` (по умолчанию 4000 мм), `--index 0`.
В PyCharm выберите `tof_viewer/app.py` и интерпретатор с зависимостями.

Нужен графический сеанс и OpenCV с поддержкой окон (не opencv-python-headless).
Для Raspberry Pi используйте работающий драйвер и ArducamDepthCamera как для
`clue/time-of-flight.py`. Tk больше не требуется. Исходные примеры не изменены.

## Управление

Ползунок **View: 0 Depth / 1 Confidence** переключает изображения мышью.
В активном окне также работают клавиши:

- **0 / D** — глубина;
- **1 / C** — confidence;
- **Пробел** — переключить режим;
- **Q / Esc** или закрытие окна — выход.

Подписи окна английские для совместимости системных бэкендов OpenCV.
Глубина — цветная карта 0…максимум диапазона, некорректные значения чёрные.
Confidence — серое изображение с фиксированной шкалой 0…255, больше — светлее.
Обрезание значений используется только при визуализации. Порога confidence нет.

## Что ускорено

Убрана пауза 40 мс после отрисовки (прежний предел был ниже 25 FPS).
Нет создания ImageTk/Canvas, преобразования BGR в RGB и масштабирования через Pillow
на каждом кадре: OpenCV получает изображение исходного размера и масштабирует окно.
Confidence передаётся как одноканальный массив.
Кадр преобразуется только при поступлении новых данных или переключении режима.
Захват работает отдельно и публикует только последний кадр. Если вывод не успевает,
промежуточные кадры пропускаются, а очередь задержки не растёт.
Копирование буферов SDK сохранено: оно нужно до вызова releaseFrame.

Раз в секунду в консоль выводятся:

- **Захват** — количество полученных кадров в секунду;
- **Вывод** — количество передач новых изображений в imshow (не частота монитора);
- **Подготовка** — среднее время преобразования массива для вывода;
- **Возраст кадра до вывода** — время после получения из SDK до вызова imshow.

Эти показатели не включают задержку внутри камеры/SDK и отображение на мониторе.
Демонстрационный источник ограничен примерно 30 FPS. Реальный предел определяется
камерой, SDK и оконным бэкендом; увеличение FPS на Raspberry Pi требует замера там.

Оконный цикл следует API OpenCV HighGUI:
https://docs.opencv.org/4.13.0/d7/dfc/group__highgui.html
