# Просмотр Arducam ToF

Самостоятельное приложение. Существующие файлы проекта не изменяются.
Python 3.10+; рекомендуется использовать тот же интерпретатор, на котором уже
работает `clue/time-of-flight.py`.

## Запуск

Из корня репозитория, в активном виртуальном окружении:

```sh
python -m pip install -r tof_workspace/requirements.txt
python tof_workspace/app.py --demo
```

На Raspberry Pi с подключённой и настроенной камерой:

```sh
python tof_workspace/app.py --index 0 --range 4000
```

`--range` задаёт аппаратный диапазон: 2000 или 4000 мм, как в исходном примере.
`--index` — индекс камеры в SDK, он не обязательно совпадает с номером CSI-разъёма.
Приложение требует графического рабочего стола; обычного SSH без дисплея недостаточно.
В PyCharm выберите `tof_workspace/app.py` как Script path, существующий Python
интерпретатор и параметры `--demo` для проверки без камеры.

Tkinter должен быть доступен в выбранном Python (`python -m tkinter` открывает
проверочное окно). Для системного Python Raspberry Pi OS пакет обычно устанавливают
через `sudo apt install python3-tk`. Python, собранный через pyenv, должен быть
собран с поддержкой Tcl/Tk; установка системного пакета не исправляет такую сборку.

ArducamDepthCamera и драйвер камеры устанавливаются отдельно **на Raspberry Pi**.
Код использует API вашего примера: `ArducamCamera`, `Connection.CSI`,
`FrameType.DEPTH`, `depth_data`, `confidence_data`. Старый API с
`getDepthData()` автоматически не подменяется.
Инструкции производителя:
[Arducam ToF SDK](https://docs.arducam.com/Raspberry-Pi-Camera/Tof-camera/Arducam-ToF-Camera-SDK/).
Не запускайте пример и приложение одновременно: оба захватывают одну камеру.

## Управление

- «Глубина: исходная» — исходные расстояния, преобразованные в цвет для просмотра.
- «Глубина: фильтр» — порог confidence, отсечение расстояний и выбранное сглаживание.
- Confidence — исходные значения доверия в градациях серого; настройка белого уровня
  меняет только отображение. Это единицы SDK, не проценты вероятности.
- Порог confidence отбрасывает ненадёжные измерения. Если камера не отдаёт confidence,
  этот фильтр пропускается и появляется сообщение.
- Минимум и максимум — программный фильтр в мм, не изменение аппаратного диапазона.
  При минимуме не меньше максимума сохраняются последние корректные настройки.
- Медианный фильтр уменьшает одиночные выбросы; Гаусс сглаживает, но размывает границы;
  билатеральный лучше сохраняет перепады глубины. Sigma задаётся в мм и влияет только
  на билатеральный фильтр. Окно — 3×3 или 5×5.
- Недостоверные точки остаются недостоверными: в обработанной глубине это NaN,
  на изображении — чёрный. Гаусс нормируется по маске валидных точек;
  медианный и билатеральный фильтры не применяются рядом с отверстиями маски.

## Структура и расширение

`camera.py` содержит класс `ToFCamera` и `DepthFrame`. Захват выполняется в одном
потоке, все вызовы SDK, включая stop/close, остаются в этом потоке. Массивы копируются
до releaseFrame и публикуются только для чтения. `latest()` возвращает последний кадр
или None, `error` — последнюю ошибку. Объект запускается один раз.

```python
from camera import ToFCamera

camera = ToFCamera().start()
try:
    # В цикле основного приложения:
    frame = camera.latest()
    if frame is not None:
        depth_mm = frame.depth
        confidence = frame.confidence
finally:
    camera.stop()
    camera.join()
```

`processing.py` — отдельные функции для будущих алгоритмов. `filter_depth()` возвращает
новую матрицу расстояний в мм, а не цветную картинку. Добавляйте алгоритмы сюда;
`app.py` вызывает их в отдельном потоке обработки. Tkinter и ImageTk используются
только в главном потоке. Захват и обработка хранят по одному последнему кадру:
при перегрузке пропускаются кадры, очередь и задержка не растут. Процессы пока не
нужны: для небольших кадров они добавили бы передачу массивов между процессами.

При закрытии окно асинхронно ждёт завершения потоков. requestFrame использует
тайм-аут 200 мс; после пяти секунд без кадров выводится ошибка. Если нативный SDK
зависнет и проигнорирует тайм-аут, Python-поток не сможет принудительно его остановить.
Повторное подключение в этой версии — перезапуск приложения.

Arduino и сервоприводы на этом этапе не запускаются. Для следующего этапа:
pyFirmata2, X — pin 9, Y — pin 10; ограничения из примера X 20–160°, Y 30–150°.

## Проверка

```sh
python -m unittest discover -s tof_workspace/tests -v
```

Тесты используют синтетические кадры и имитацию SDK: проверяют копирование буферов,
освобождение камеры после ошибки, остановку потока и обработку недостоверных точек.
На устройстве дополнительно проверьте все режимы, настройки фильтров, отключение
камеры, закрытие окна и повторный запуск. Реальная плавность зависит от SDK,
разрешения, экспозиции и нагрузки Raspberry Pi; фиксированный FPS не гарантируется.
